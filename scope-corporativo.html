Observação estratégica sobre a arquitetura de subdomínios:
Os dois canais principais operam em subdomínios separados (loja. e corporativo.). Esta é a decisão arquitetural mais impactante para o crescimento orgânico de longo prazo do canal corporativo e é abordada em detalhe na seção Estratégico.

P.3 2 Produtos — Price gating bloqueia rich snippets Ruim
Evidência corporativo.elements.com.br/products/cadeira-ergonomica-elements-astra
Mensagem exibida: "Cadastre-se e veja os preços". Preços só visíveis após cadastro com CNPJ. O Googlebot não possui CNPJ — não consegue rastrear preços. Resultado: Product schema não pode incluir PriceSpecification → página não é elegível para rich snippet de produto com preço. Schema markup não confirmado via WebFetch (injetado via JS Shopify).
Benchmark de mercado Plataformas B2B que resolvem este conflito usam: (a) preço "a partir de" visível publicamente com markup minPrice, (b) faixa de preço por linha de produto sem preço exato, (c) schema Product com offers apontando para "disponível mediante cadastro" com @type: Offer, availability: PreOrder como indicativo de acesso restrito.
Recomendação Implementar na ficha de produto um preço de tabela público (ex.: "A partir de R$ X.XXX") visível sem login, com markup de schema. O preço final (com desconto CNPJ) permanece gated. Esta abordagem preserva o modelo de negócio B2B e permite indexação de preços base no Google Shopping e rich snippets.
Impacto esperadoElegibilidade para rich snippets de produto com preço no Google — diferencial importante no SERP para buscas corporativas.

P.5 1 Produtos — Schema com Preço vs UI Gated: Risco de "Dados Estruturados Enganosos" Crítico
⚠️
Contradição schema vs UI — risco de penalidade por dados estruturados enganosos
O schema JSON-LD expõe o preço ao Googlebot, mas a UI exige login com CNPJ para exibir o mesmo preço. O Google considera isso "misleading structured data" e pode desqualificar o schema inteiro.
Evidência — Confirmado via DevTools (Setembro 2026) corporativo.elements.com.br/products/cadeira-ergonomica-elements-astra
JSON-LD ProductGroup schema confirmado:
"@type": "ProductGroup"
"offers": { "price": 1167.37, "priceCurrency": "BRL", "availability": "InStock" }

UI para usuário não autenticado:
Mensagem: "Cadastre-se e veja os preços" — preços ocultos atrás de login com CNPJ.

Contradição: o Googlebot vê preço R$1.167,37 no schema; o usuário não vê preço algum.
Benchmark / Diretrizes Google A documentação de dados estruturados do Google exige que o conteúdo marcado seja visível ao usuário. Um preço em schema não visível na UI é classificado como "conteúdo oculto no schema" — pode resultar em ação manual (remoção de rich snippets) ou penalidade de qualidade.
Recomendação — 2 caminhos Caminho 1 (preferido): Exibir preço base público ("A partir de R$ X.XXX") na UI — consistente com o schema. O preço final (com desconto CNPJ) continua gated. Atualiza o schema para mostrar o mesmo preço base.
Caminho 2: Remover o campo offers.price do schema e usar "offers.availability": "SeeAlsoSection" com URL de cadastro — compatível com modelo B2B gated sem risco de misleading data.
Impacto esperadoEliminação de risco de ação manual por dados estruturados enganosos. Habilitação de rich snippets de produto com preço público.
P.6 3 Organization Schema — sameAs com Strings Vazias Regular
Evidência — DevTools (Setembro 2026) corporativo.elements.com.br/
Organization schema confirmado via DevTools. Campo sameAs encontrado com array de strings vazias:
"sameAs": ["", ""]
Valor esperado: URLs de perfis sociais oficiais (ex: Instagram, LinkedIn, YouTube da marca).

Análise: O campo sameAs no Organization schema é usado pelo Google para associar a entidade da marca aos seus perfis sociais e criar conexões no Knowledge Graph. Strings vazias não geram erro de validação, mas desperdiçam a oportunidade de consolidar a identidade da marca.

Recomendação Preencher sameAs com as URLs oficiais de redes sociais da marca:
"sameAs": ["https://www.instagram.com/elements.oficial/", "https://www.linkedin.com/company/elements-br/", ...]
Configurar via tema Shopify ou app de SEO que gera o Organization schema.
Impacto esperadoConsolidação de entidade de marca no Knowledge Graph do Google. Associação dos perfis sociais à entidade corporativa.

Estratégico Arquitetura de Domínio e Oportunidades Estruturais
E.1 2 Arquitetura — Subdomain split: autoridade dividida entre loja e corporativo Ruim
Evidência estrutural Dois Shopify stores independentes: loja.elements.com.br (B2C) e corporativo.elements.com.br (B2B). Cada um possui seu próprio sitemap, robots.txt e histórico de rastreamento separados. Google Search Console trata como duas propriedades distintas. Backlinks adquiridos para loja não beneficiam corporativo e vice-versa.
Benchmark de mercado Do ponto de vista de SEO puro, a arquitetura ideal seria subdirectory (elements.com.br/corporativo/) que consolida toda a autoridade de domínio em um único site. No entanto, esta migração de duas stores Shopify para uma única é operacionalmente complexa e envolve decisões de negócio (controle de acesso B2B por CNPJ, preços diferenciados, catálogo curado). Empresas como Grainger (EUA) e Unilab (BR) optaram por subdomain justamente por necessidade de controle de acesso B2B — a decisão tem justificativa operacional.
Recomendação Hipótese: a arquitetura atual (dois subdomínios) é uma decisão de produto, não de SEO. O caminho de menor custo para mitigar o impacto no orgânico é: (1) Construir autoridade de forma independente para corporativo via blog B2B ativo (BL.1), (2) Criar interlinking entre os dois subdomínios — rodapé/cabeçalho de cada store apontar para o outro, (3) Garantir que os links externos (PR, parceiros, associações) mencionem e linkem para corporativo.elements.com.br especificamente. Migração para subdirectory: avaliar no longo prazo com análise de ROI — não é ação de Sprint 1.
