3.3 INP Mobile 304ms — Core Web Vitals FAILED (todo o site) 2
// Fato Observado — PageSpeed Insights (field data, dados reais de usuário)
URL analisada: https://loja.elements.com.br/
INP mobile: 304ms → NEEDS IMPROVEMENT / status geral: FAILED
Threshold Google: <200ms = Good · 200–500ms = Needs Improvement · >500ms = Poor

CLS mobile: 0.0 → GOOD ✅
Causa raiz identificada: scripts de terceiros (Meta Pixel, chat widget, apps Shopify) bloqueando main thread durante interações do usuário.

Análise: O INP mede o tempo de resposta a interações (clique, toque). Com 304ms, o site está na zona "Needs Improvement" — basta esse único valor fora do threshold para o assessment ser FAILED. O Google usa CWV como fator de ranking em mobile-first indexing; concorrentes com PASSED têm vantagem direta de posicionamento para as mesmas keywords.

Benchmark
E-commerces líderes no segmento mantêm INP <150ms mobile. Verificar Flexform e Sidiz com PageSpeed Insights — se estiverem PASSED, a Elements está em desvantagem de ranking direto.
Recomendação
1. Chrome DevTools → Performance → Long Tasks: identificar qual script causa o bloqueio.
2. Meta Pixel: implementar carregamento lazy (após first user interaction).
3. Chat widget: configurar para iniciar após 4–5s ou após scroll do usuário.
4. Apps Shopify: auditar todos os apps instalados; desativar os não essenciais (cada app adiciona ~50–200ms ao INP).
Impacto: INP <200ms → CWV Assessment PASSED → desbloqueio do Page Experience Signal em mobile.

B.1 Heading Structure — H1 Múltiplos em Artigos do Blog 1
// Fato Observado — loja.elements.com.br/blogs/artigos/[artigo] (múltiplos artigos verificados)
Problema encontrado: múltiplos elementos H1 por página de artigo.
Padrão sistêmico — afeta todos os artigos do blog (/blogs/artigos/).
Origem provável: template do artigo (article.liquid ou sections do blog) usando H1
em mais de um lugar (ex: título do artigo + títulos de seções internas).
Total de URLs afetadas: 185 artigos indexados.

Análise: O H1 é o sinal semântico principal que o Google usa para entender o tópico de uma página. Com múltiplos H1s em cada artigo, o rastreador não consegue determinar qual é o tópico central — a relevância se dilui entre todos os elementos. Para um blog com 185 artigos cobrindo temas específicos (ergonomia, home office, mesas elétricas), esse problema impede que cada artigo ranqueie de forma eficiente para sua keyword-alvo.

Benchmark de mercado
Blogs líderes em SEO mantêm rigorosamente 1 único H1 por artigo — o título da publicação. Subtítulos de seção usam H2; subseções usam H3. Essa hierarquia ajuda o Google a entender a estrutura do conteúdo e aumenta a probabilidade de rich snippets de artigo.
Recomendação
Correção no template Shopify do blog:
1. Shopify Admin → Online Store → Themes → Edit Code → templates/article.liquid (ou sections equivalentes).
2. Identificar todos os elementos H1 — apenas o título do artigo deve usar H1: <h1>{{ article.title }}</h1>
3. Converter demais H1s para H2 ou H3 conforme a hierarquia do conteúdo.
4. Verificar nas sections do tema (sections/article-template.liquid) se há uso de H1 em seções laterais ou de destaque.
5. Após publicação, validar com extensão SEO META in 1 CLICK em 5–10 artigos.
Testar em tema duplicado antes de publicar em produção.
Impacto esperado: Clareza semântica em 185 artigos indexados simultaneamente. Potencial de melhora de posição para keywords de cauda longa de blog em 30–60 dias após reindexação.

P.1 Meta Descriptions — Ausentes / Auto-geradas em 395 PDPs 2
// Fato Observado — loja.elements.com.br/products/[produto] (múltiplos produtos verificados)

Análise: A meta description não afeta ranking diretamente, mas é o principal driver de CTR orgânico — o usuário na SERP decide clicar baseado no snippet. Um snippet auto-gerado perde CTR para concorrentes que têm meta descriptions com keyword + benefício + CTA.

Benchmark

Camada 2 — meta descriptions manuais para top PDPs:
Para os 20–30 produtos com maior volume de busca: Shopify Admin → Produto → SEO → Meta description.
Impacto esperado: +15–30% CTR orgânico em PDPs com meta descriptions otimizadas. Mensurável via GSC → Desempenho → CTR em 30–45 dias.

O valor correto seria "Elements" — "elementsbr" é provavelmente o handle interno da marca no Shopify.
Impacto: o Google associa o sinal de marca ao identificador "elementsbr" em vez de "Elements".

Análise: O schema de marca é um dos principais sinais que o Google usa para construir o Knowledge Graph da marca. Um brand.name incorreto ou técnico ("elementsbr") dificulta a associação da entidade-produto à marca "Elements" no grafo de conhecimento do Google. Isso pode reduzir a elegibilidade para rich snippets de produto com nome de marca e enfraquecer o sinal de entidade para consultas de brand.

Recomendação
No Shopify Admin → Configurações → Dados da loja → Nome da marca (ou equivalente no tema). Verificar qual campo popula o brand.name no JSON-LD — geralmente é o nome da loja ou um metafield. Atualizar para "Elements".
Validar a correção em: search.google.com/test/rich-results após publicar.
Impacto: Correção de associação de entidade de marca no Knowledge Graph. Elegibilidade aprimorada para rich snippets de produto com nome de marca.
P.4 BreadcrumbList Duplicado em Páginas de Produto 3
// Fato Observado — DevTools · JSON-LD verificado em PDPs (Setembro 2026)
Encontrados 2 scripts JSON-LD com @type BreadcrumbList na mesma página de produto.
Origem provável: tema + app Shopify injetando schema de breadcrumb independentemente.
Conteúdo verificado: ambos os schemas presentes simultaneamente na DOM renderizada.

Análise: O Google documenta explicitamente que múltiplos schemas do mesmo tipo na mesma página podem gerar conflito de interpretação. Com dois BreadcrumbList, o rastreador precisa decidir qual usar — o que pode resultar em rich snippet incorreto ou na não exibição do breadcrumb na SERP.

Recomendação
1. Identificar qual dos dois BreadcrumbList é injetado pelo tema e qual por app (DevTools → inspecionar atributos do script).
2. Manter apenas o BreadcrumbList do tema base (mais confiável e controlável).
3. Desabilitar a injeção de breadcrumb schema pelo app responsável.
4. Validar no Rich Results Test após correção.
Impacto: Eliminação de conflito de schema. Consistência na exibição de breadcrumbs na SERP.
Conclusão Estratégica — Produtos

As páginas de produto têm boa base estrutural (URLs limpas, breadcrumbs, reviews). O gap principal é de CTR — meta descriptions auto-geradas estão perdendo cliques orgânicos que já existem. C.3 /collections/all — H1 "All Products" em Inglês (Bug de Localização) 3
// Fato Observado — DevTools · loja.elements.com.br/collections/all (Setembro 2026)
URL: https://loja.elements.com.br/collections/all
H1 confirmado via DevTools: "All Products" (em inglês)
URL equivalente em português: /collections/todos-os-produtos → H1: "Todos os Produtos"
Ambas as páginas indexadas independentemente.

Análise: A URL /collections/all é gerada automaticamente pelo Shopify como coleção padrão "todos os produtos". Como o tema não sobrescreve o H1 dessa coleção específica, ela exibe "All Products" em inglês — contradição direta em um site inteiramente em português. Isso enfraquece o sinal de relevância para queries em português e cria inconsistência de experiência de usuário.

Recomendação
Solução preferida: criar 301 redirect de /collections/all → /collections/todos-os-produtos (recomendação do item C.1).
Alternativa: sobrescrever o título da coleção "all" diretamente no Shopify Admin → Coleções → "Todos os produtos" → campo de título.
Impacto: Eliminação de H1 em inglês em site português. Consolidação de autoridade via redirect.

Metodologia da Projeção

Como calculamos a projeção

A projeção combina três variáveis mensuráveis com dados reais do Semrush Set 2026 e benchmarks de CTR por posição (fonte: Backlinko, "Google CTR Stats and Facts", 2022 — dados mobile por posição orgânica, mercado global; adaptado para o Brasil com conservadorismo de ~15% dado comportamento mobile local):

FATOR 1
Posição Atual × CTR
Posições Semrush + curva CTR por posição. #1=27.6%, #2=15.8%, #3=11%, #4=8.4%, #5=6.3%.
FATOR 2
Ganho de Posição por CWV
Correlação Google CWV × ranking: sites que passam de FAILED para PASSED ganham em média 1–3 posições em keywords competitivas top 10.
FATOR 3
Ganho por Otimização de Conteúdo
H1 + meta descriptions + coleções otimizadas = acesso a keywords de alto volume hoje fora do top 10 (ex: "cadeira de escritorio" 201K vol).
⚠️ Nota metodológica: Projeções de SEO são probabilísticas, não determinísticas. Os cenários apresentados são estimativas conservadoras baseadas em dados observados. Resultados reais dependem de execução técnica, timing de reindexação e movimentos de concorrentes. Google Search Console conectado permitiria precisão significativamente maior.

Diagnóstico em uma frase

A Elements Loja é o segundo maior player orgânico do segmento de cadeiras ergonômicas com ~124K visitas/mês e posição #1 na keyword principal — mas opera com uma falha crítica de performance mobile (INP 304ms) que expõe sua liderança ao risco, e está completamente ausente de "cadeira de escritorio" (201K vol), o maior cluster do segmento, onde o concorrente Flexform coleta 26.500 visitas/mês sozinho. Corrigir essas duas lacunas pode elevar o tráfego em até 48% em 6 meses, superando Flexform como líder orgânico.

Achados Críticos · Elements Loja
❌
INP 304ms mobile → CWV FAILED (todo o site)
Principal risco de posição: DT3 tem PASSED em ambos os dispositivos. Se o Google pesar mais o sinal CWV, a Elements perde posições para DT3 em "cadeira ergonomica". A causa raiz são scripts de terceiros (Meta Pixel, chat widget, apps Shopify) no main thread mobile.

Conclusão da Auditoria S.C.O.P.E.

A Elements Loja tem os ativos certos para liderar o mercado orgânico de ergonomia no Brasil: autoridade topical confirmada, backlinks, tráfego de 124K/mês e posição #1 na keyword principal. O que falta são três ajustes técnicos e de conteúdo que estão claramente mapeados nesta análise. Comparativamente, Flexform lidera por tráfego mas falha no mesmo ponto de CWV (mobile FAILED) — e DT3, que tem PASSED nos dois dispositivos, tem menos autoridade topical e menos tráfego. A janela de oportunidade para a Elements se tornar a referência orgânica número 1 do segmento está aberta. A pergunta não é se dá — é quando começa.
