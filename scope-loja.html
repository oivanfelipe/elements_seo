3.3 INP Mobile 304ms — Core Web Vitals FAILED (todo o site) 2
// Fato Observado — PageSpeed Insights (field data, dados reais de usuário)
URL analisada: https://loja.elements.com.br/
INP mobile: 304ms → NEEDS IMPROVEMENT / status geral: FAILED
Threshold Google: <200ms = Good · 200–500ms = Needs Improvement · >500ms = Poor
LCP mobile: 1.5s → GOOD ✅
CLS mobile: 0.0 → GOOD ✅
Causa raiz identificada: scripts de terceiros (Meta Pixel, chat widget, apps Shopify) bloqueando main thread durante interações do usuário.

Análise: O INP mede o tempo de resposta a interações (clique, toque). Com 304ms, o site está na zona "Needs Improvement" — basta esse único valor fora do threshold para o assessment ser FAILED. O Google usa CWV como fator de ranking em mobile-first indexing; concorrentes com PASSED têm vantagem direta de posicionamento para as mesmas keywords.

Benchmark
E-commerces líderes no segmento mantêm INP <150ms mobile. Verificar Flexform e Sidiz com PageSpeed Insights — se estiverem PASSED, a Elements está em desvantagem de ranking direto.
Recomendação
1. Chrome DevTools → Performance → Long Tasks: identificar qual script causa o bloqueio.
2. Meta Pixel: implementar carregamento lazy (após first user interaction).
3. Chat widget: configurar para iniciar após 4–5s ou após scroll do usuário.
4. Apps Shopify: auditar todos os apps instalados; desativar os não essenciais (cada app adiciona ~50–200ms ao INP).
Impacto: INP <200ms → CWV Assessment PASSED → desbloqueio do Page Experience Signal em mobile.

1.4 Homepage — H1 "Mais vendidas" (Carousel Section Heading) 3
// Fato Observado — DevTools · loja.elements.com.br/ (Homepage)
H1 da homepage confirmado via DevTools: "Mais vendidas"
Origem: heading de uma seção de carrossel de produtos (ex: "Mais vendidas" = seção de bestsellers).
Não representa a proposta de valor da marca nem as keywords-alvo de categoria (ex: "Cadeiras Ergonômicas e Mesas Elétricas").

Análise: O H1 da homepage é o sinal semântico primário que o Google usa para entender o tópico central da página mais importante do domínio. "Mais vendidas" é um título de seção de navegação — não transmite ao rastreador sobre o que é o site. Concorrentes com H1 "Cadeiras Ergonômicas e Mesas de Escritório" ou "Móveis Ergonômicos para Home Office" têm vantagem direta de relevância para essas queries de alto volume.

Benchmark
Homepages de e-commerce líderes em SEO usam H1 com keyword de categoria + diferencial de marca: "Cadeiras Ergonômicas e Mesas Eletrônicas | Elements — Ergonomia para Trabalho e Home Office".
Recomendação
Shopify → Tema → sections/main-index.liquid (ou seção hero/banner principal).
Substituir o H1 "Mais vendidas" (que deve ser um H2 ou H3) por um H1 de brand + categoria:
Ex: "Cadeiras Ergonômicas e Mesas Elétricas — Elements"
A seção de bestsellers deve usar H2 ou H3 para o título da seção.
Impacto: H1 relevante na homepage = sinal semântico principal corrigido para a página de maior autoridade do domínio.
Conclusão — Técnico

A infraestrutura da Elements é a mais saudável do site (score 3.9). O LCP excelente de 1.5s mobile é uma vantagem real. Quatro itens de correção rápida: H1 da homepage (heading de seção em vez de brand + categoria), página de teste no sitemap, INP 304ms mobile e BreadcrumbList duplicado em PDPs. Todos têm caminhos de correção diretos no Shopify.

B.1 Heading Structure — H1 Múltiplos em Artigos do Blog 1
// Fato Observado — loja.elements.com.br/blogs/artigos/[artigo] (múltiplos artigos verificados)
Problema encontrado: múltiplos elementos H1 por página de artigo.
Padrão sistêmico — afeta todos os artigos do blog (/blogs/artigos/).
Origem provável: template do artigo (article.liquid ou sections do blog) usando H1
em mais de um lugar (ex: título do artigo + títulos de seções internas).
Total de URLs afetadas: 185 artigos indexados.

Análise: O H1 é o sinal semântico principal que o Google usa para entender o tópico de uma página. Com múltiplos H1s em cada artigo, o rastreador não consegue determinar qual é o tópico central — a relevância se dilui entre todos os elementos. Para um blog com 185 artigos cobrindo temas específicos (ergonomia, home office, mesas elétricas), esse problema impede que cada artigo ranqueie de forma eficiente para sua keyword-alvo.

Benchmark de mercado
Blogs líderes em SEO mantêm rigorosamente 1 único H1 por artigo — o título da publicação. Subtítulos de seção usam H2; subseções usam H3. Essa hierarquia ajuda o Google a entender a estrutura do conteúdo e aumenta a probabilidade de rich snippets de artigo.
Recomendação
Correção no template Shopify do blog:
1. Shopify Admin → Online Store → Themes → Edit Code → templates/article.liquid (ou sections equivalentes).
2. Identificar todos os elementos H1 — apenas o título do artigo deve usar H1: <h1>{{ article.title }}</h1>
3. Converter demais H1s para H2 ou H3 conforme a hierarquia do conteúdo.
4. Verificar nas sections do tema (sections/article-template.liquid) se há uso de H1 em seções laterais ou de destaque.
5. Após publicação, validar com extensão SEO META in 1 CLICK em 5–10 artigos.
Testar em tema duplicado antes de publicar em produção.
Impacto esperado: Clareza semântica em 185 artigos indexados simultaneamente. Potencial de melhora de posição para keywords de cauda longa de blog em 30–60 dias após reindexação.

Análise: Para artigos sobre ergonomia e saúde ocupacional, o Google aplica critérios de E-E-A-T com rigor maior do que para conteúdo neutro. 4. Para artigos de saúde/ergonomia: incluir revisão de fisioterapeuta ou ergonomista com byline visível.
Impacto esperado: Melhora de E-E-A-T sinalizado ao Google. Elegibilidade para rich snippets de artigo com byline. Maior credibilidade para usuário em fase de consideração.

A boa notícia: o conteúdo já existe — o trabalho é de requalificação, não de criação do zero. Corrigi-las sequencialmente (template → autores → links → clusters) tem retorno alto com esforço relativamente baixo.

P.1 Meta Descriptions — Ausentes / Auto-geradas em 395 PDPs 2
// Fato Observado — loja.elements.com.br/products/[produto] (múltiplos produtos verificados)
Meta descriptions: auto-geradas pelo Shopify a partir do início da descrição do produto.
Resultado típico no snippet da SERP:
"Cadeira Ergonômica X. Conheça a linha de cadeiras Elements. Feita com materiais de..."

Problemas identificados:
- Sem keyword principal explícita no início
- Sem benefício diferencial
- Sem CTA (frete grátis, parcelamento, entrega)
- Texto truncado sem mensagem completa

Análise: A meta description não afeta ranking diretamente, mas é o principal driver de CTR orgânico — o usuário na SERP decide clicar baseado no snippet. Um snippet auto-gerado perde CTR para concorrentes que têm meta descriptions com keyword + benefício + CTA.

Benchmark
E-commerces líderes no formato: "[Keyword principal] — [benefício diferencial]. Frete grátis + entrega em X dias. [X]x sem juros." CTR 20–40% maior vs. snippets auto-gerados em testes A/B documentados.
Recomendação
Camada 1 — template dinâmico (cobre as 395 PDPs imediatamente):
Editar theme.liquid para gerar: "{{ product.title }} na Elements — {{ product.metafields.custom.beneficio }}. Frete grátis. [X]x sem juros."

Camada 2 — meta descriptions manuais para top PDPs:
Para os 20–30 produtos com maior volume de busca: Shopify Admin → Produto → SEO → Meta description.
Impacto esperado: +15–30% CTR orgânico em PDPs com meta descriptions otimizadas. Mensurável via GSC → Desempenho → CTR em 30–45 dias.

Shopify Admin → Produtos → editar imagem → campo Alt Text.
Padrão ideal: "[Nome do produto] — [atributo principal] — Elements".
Ex: "Cadeira Ergonômica Mesh Pro preta reclinável — Elements".
Priorizar: imagem principal (primeira foto) de cada produto, pois é a mais rastreada.
Impacto: Elegibilidade para Google Images. Reforço semântico de keyword nas PDPs.
P.3 Product Schema — brand.name = "elementsbr" em Vez de "Elements" 3
// Fato Observado — DevTools · JSON-LD ProductGroup schema (loja.elements.com.br/products/)
ProductGroup schema verificado via DevTools em páginas de produto:
"brand": { "@type": "Brand", "name": "elementsbr" }
O valor correto seria "Elements" — "elementsbr" é provavelmente o handle interno da marca no Shopify.
Impacto: o Google associa o sinal de marca ao identificador "elementsbr" em vez de "Elements".

Análise: O schema de marca é um dos principais sinais que o Google usa para construir o Knowledge Graph da marca. Um brand.name incorreto ou técnico ("elementsbr") dificulta a associação da entidade-produto à marca "Elements" no grafo de conhecimento do Google. Isso pode reduzir a elegibilidade para rich snippets de produto com nome de marca e enfraquecer o sinal de entidade para consultas de brand.

Recomendação
No Shopify Admin → Configurações → Dados da loja → Nome da marca (ou equivalente no tema). Verificar qual campo popula o brand.name no JSON-LD — geralmente é o nome da loja ou um metafield. Atualizar para "Elements".
Validar a correção em: search.google.com/test/rich-results após publicar.
Impacto: Correção de associação de entidade de marca no Knowledge Graph. Elegibilidade aprimorada para rich snippets de produto com nome de marca.
P.4 BreadcrumbList Duplicado em Páginas de Produto 3
// Fato Observado — DevTools · JSON-LD verificado em PDPs (Setembro 2026)
Encontrados 2 scripts JSON-LD com @type BreadcrumbList na mesma página de produto.
Origem provável: tema + app Shopify injetando schema de breadcrumb independentemente.
Conteúdo verificado: ambos os schemas presentes simultaneamente na DOM renderizada.

Análise: O Google documenta explicitamente que múltiplos schemas do mesmo tipo na mesma página podem gerar conflito de interpretação. Com dois BreadcrumbList, o rastreador precisa decidir qual usar — o que pode resultar em rich snippet incorreto ou na não exibição do breadcrumb na SERP.

Recomendação
1. Identificar qual dos dois BreadcrumbList é injetado pelo tema e qual por app (DevTools → inspecionar atributos do script).
2. Manter apenas o BreadcrumbList do tema base (mais confiável e controlável).
3. Desabilitar a injeção de breadcrumb schema pelo app responsável.
4. Validar no Rich Results Test após correção.
Impacto: Eliminação de conflito de schema. Consistência na exibição de breadcrumbs na SERP.
Conclusão Estratégica — Produtos

As páginas de produto têm boa base estrutural (URLs limpas, breadcrumbs, reviews). O gap principal é de CTR — meta descriptions auto-geradas estão perdendo cliques orgânicos que já existem. Dois problemas de schema confirmados via DevTools (brand.name errado e BreadcrumbList duplicado) são correções de impacto médio-alto com esforço baixo. A implementação de template de meta description dinâmico no theme.liquid continua sendo a ação de maior ROI por unidade de esforço nessa área.

C.1 Coleções Duplicadas — 2 Pares de URLs para o Mesmo Conteúdo 2
// Fato Observado — sitemap_collections_1.xml + DevTools (verificação independente, Setembro 2026)
Par duplicado 1:
> https://loja.elements.com.br/collections/mais-vendidas
> https://loja.elements.com.br/collections/mais-vendidos
(variação de gênero no slug — mesmo conteúdo; ambas abertas e indexáveis sem redirecionamento entre si)

Par duplicado 2:
> https://loja.elements.com.br/collections/all (padrão Shopify · H1: "All Products" — em inglês)
> https://loja.elements.com.br/collections/todos-os-produtos (URL em português · H1 correto)
Confirmado via DevTools: ambas as URLs carregam independentemente sem canonical cruzado ou 301 entre si.

Análise: Cada par divide a autoridade de link entre duas URLs que deveriam ser uma só. O Google frequentemente alterna qual versão ranquear — resultando em instabilidade de posição. Além disso, o crawl budget do Googlebot é consumido duas vezes para o mesmo conteúdo.

Recomendação
1. Decidir a URL canônica de cada par:
  — Manter /collections/mais-vendidos → redirecionar /mais-vendidas
  — Manter /collections/todos-os-produtos → redirecionar /all (slug mais descritivo para busca BR)
2. Criar 301 redirects: Shopify Admin → Online Store → Navigation → URL Redirects.
3. Atualizar links internos que apontem para as URLs descontinuadas.
Impacto: Consolidação de autoridade nas URLs canônicas. Estabilização de posições para keywords de categoria.
C.2 Copy de Categoria — Coleções Principais Sem Texto SEO 3
// Fato Observado — coleções principais verificadas
https://loja.elements.com.br/collections/cadeiras-ergonomicas → sem texto introdutório
https://loja.elements.com.br/collections/mesas-com-motorizado → sem texto introdutório
Conteúdo visível: apenas grid de produtos + filtros.

Análise: Páginas de coleção sem texto de categoria não têm como ranquear para keywords amplas de categoria ("cadeiras ergonômicas", "mesa elétrica escritório"). Sem conteúdo textual, o Google não tem base para associar a página a essas queries de alto volume — e direciona o ranqueamento para PDPs individuais, que têm menor autoridade de link do que a coleção.

Recomendação
Shopify Admin → Collections → [coleção] → Description.
Estrutura ideal (150–250 palavras): H2 com keyword principal + parágrafo de introdução + lista de diferenciais + link para artigo de guia de compra do cluster.
Prioridade: /collections/cadeiras-ergonomicas e /collections/mesas-com-motorizado primeiro.
Impacto: Elegibilidade para ranqueamento de keywords de categoria de alto volume. Autoridade temática reforçada nas páginas de maior valor comercial.
C.3 /collections/all — H1 "All Products" em Inglês (Bug de Localização) 3
// Fato Observado — DevTools · loja.elements.com.br/collections/all (Setembro 2026)
URL: https://loja.elements.com.br/collections/all
H1 confirmado via DevTools: "All Products" (em inglês)
URL equivalente em português: /collections/todos-os-produtos → H1: "Todos os Produtos"
Ambas as páginas indexadas independentemente.

Análise: A URL /collections/all é gerada automaticamente pelo Shopify como coleção padrão "todos os produtos". Como o tema não sobrescreve o H1 dessa coleção específica, ela exibe "All Products" em inglês — contradição direta em um site inteiramente em português. Isso enfraquece o sinal de relevância para queries em português e cria inconsistência de experiência de usuário.

Recomendação
Solução preferida: criar 301 redirect de /collections/all → /collections/todos-os-produtos (recomendação do item C.1).
Alternativa: sobrescrever o título da coleção "all" diretamente no Shopify Admin → Coleções → "Todos os produtos" → campo de título.
Impacto: Eliminação de H1 em inglês em site português. Consolidação de autoridade via redirect.
Conclusão Estratégica — Coleções

As páginas de coleção são as mais importantes para keywords de categoria (alto volume, alta intenção de compra) e são atualmente as mais negligenciadas em SEO on-page. A combinação de coleções duplicadas + sem copy + sem meta description + H1 em inglês na coleção padrão é o que explica por que a Elements pode ter dificuldade de ranquear para "cadeiras ergonômicas" e "mesa elétrica". As correções (redirects, copy, meta descriptions) podem ser executadas em uma semana diretamente no Shopify Admin.
